# 数据采集协议

本文件只规定记录怎么采。进化算法、编辑器和评测脚本都还没有写。

## 回路

对每一个候选修改：

1. **父代运行。** 用当前 harness 和固定配置跑选定任务，留下可复现的父代轨迹与分数。
2. **修改计划。** 计划可以同时改多个组件。计划正文属于训练样本，不能事后只靠 diff 反推。
3. **固定编辑器打补丁。** 编辑器本身不参加进化。补丁没打上时记为 `apply-failure`，不要把它写成该方法在任务上得了零分。
4. **子版本。** 补丁落在 Terminus2 的 harness 组件上。不改基座模型，不改 Harbor。
5. **同配置前后对比。** 用与父代相同的任务配置比较子版本。
6. **第二批泛化。** 再用另一批任务看这次修改是否只对第一批有效。
7. **完整记录。** 写入第三层。四类结果都要留：`success`、`no-effect`、`regression`、`apply-failure`。环境故障（容器、网络、评分器崩溃）与方法失败分开记。

训练样本是「计划 + 这次执行的结果」，不是单独一份最终 diff。

## 三层各放什么

| 层 | 位置 | 谁产生 | 说明 |
| --- | --- | --- | --- |
| 1 任务 | `data/tasks/` | 外部任务，入口可适配 | 1000 道 ModularRSI 终端任务：120 道带标签训练题，880 道带标签任务池。任务池用来抽取进化任务，不是留出测试集。保留说明、环境、测试、参考解、容器和评分器。可以改入口，不要把任务摊成问答文本。索引以后再写。这一步不下载数据。 |
| 2 执行 | `data/executions/` | 我们自己跑 | 父代、子代、同配置对比和泛化批的轨迹与分数。 |
| 3 修改 | `data/modifications/` | 我们自己记 | 计划、触及的组件、补丁是否应用、结果类别、环境故障标记。 |

## 两项研究怎么用同一条记录

- 研究 1，长程价值：从同一个子版本再开蒙特卡洛分叉。分叉仍走上面的执行与记录。
- 研究 2，联合修改：依赖图是输入，写进修改计划。联合方案成功，只说明这一组改动一起可用，不能据此把图里每一条依赖标成正确。

## 公开轨迹只供对照格式

ModularRSI 的 267 条公开轨迹，以及固定 harness 的重复评测，以后可以用来看记录字段长什么样。它们不是本项目的训练集。初始化这一步不下载这些轨迹，也不下载 DGM 外部日志。
